# 用我的声音生成 TTS

## 固定配置

- CLI：`/opt/homebrew/bin/speech`
- 子命令/引擎：`speech speak --engine cosyvoice`
- 参考音频：`/Users/world/Library/Caches/audio.soniqo.studio/references/haoqin-25-52791d24.mp3`
- 参考音频文本（必须原样传入 `--cosy-reference-transcript`）：
  `今天的天气还不错，我准备出去走一走。最近我一直在尝试一些新的工具，希望能找到更简单、更高效的方法。对我来说，最重要的不是功能有多少，而是它能不能真正解决问题，用起来是不是足够自然。`
- 默认语言：`chinese`
- 默认输出：WAV，保存到 `~/Downloads/`

## 交互步骤

1. 从用户消息/提供的稿件中取得完整待合成文本。若文本尚未提供，先请用户提供。**不可在用户选定模式前开始合成。**
2. **每次生成前都必须主动显示完整的 A–E 菜单并询问用户选择；没有默认模式，不得因用户没选而自行决定，也不得跳过询问。** 即使用户已提供文本或提及风格，也先显示菜单，除非用户在本轮明确选择了菜单选项。

   固定菜单内容如下，必须直接展示 D 的名称和简短说明，不得把个人预设藏在 C/E 的子菜单里：

   - **A. 自然模式**：不添加 `--cosy-instruct`。
   - **B. AI 自动匹配**：根据全文内容自动决定合适的表达方式；保持自然、克制，不逐句频繁切换风格，避免 AI 配音腔。需要风格指令时使用 `--cosy-instruct`。
   - **C. 手动选择**：用户可输入英文原名或对应中文名称；两种写法映射到同一风格，最终将英文原名作为 `--cosy-instruct`：
     - `soft` — 轻柔
     - `warm` — 温暖
     - `whispering` — 耳语
     - `intense` — 强烈
     - `excited` — 兴奋
     - `happy` — 开心
     - `calm` — 平静
     - `serious` — 严肃
     - `surprised` — 惊讶
     - `sad` — 悲伤
     - `angry` — 愤怒
     - `dramatic` — 戏剧化
     - `laughs` — 带笑声
   - **D. 我的知识旁白**：个人预设——自然、平和、亲切、克制的讲述，正常语速，转折和重点轻微强调，不夸张、无明显 AI 配音腔。将下方固定完整要求原样作为 `--cosy-instruct` 传入：
     `自然、平和、亲切、克制地讲述，保持正常自然语速；根据内容的转折和重点做轻微强调，不夸张，不使用明显的 AI 配音腔，整体像本人自然地向观众讲解内容。`
   - **E. 自定义**：询问用户输入自然语言风格要求，并将其作为 `--cosy-instruct`。

   以后新增的个人预设也必须作为独立选项直接列在主菜单中，并显示名称与简短说明。
3. 只有用户明确选择 A–E（以及 C/E 所需风格）后才生成。若用户只提供文本而没有明确选择，显示完整菜单并等待选择。

## 生成前检查与安全

- 如 CLI 参数不确定，先执行 `/opt/homebrew/bin/speech speak --help` 核实，不猜参数。
- 确认 CLI、参考音频存在；只读检查，不修改参考音频或 Speech Studio。
- **禁止下载或安装模型，禁止更换/指定模型变体。** 不传 `--model-id`、`--cosyvoice-variant` 等模型选择参数。仅使用已缓存的默认 CosyVoice3 模型；如果不能确认所需模型已在本机缓存，或运行提示需要下载，停止并告知用户，不继续触发下载。
- 短文本一次生成；长文本按下文流程自动分段。中间文件只能放入本次任务独立的临时目录；不改动参考音频、Speech Studio 或其他无关文件。
- 只使用现有模型缓存；运行若提示下载模型，立即停止，不触发下载。

## Markdown → 朗读用纯文本

当输入来源是 `.md` 文件时，先生成仅供本次朗读/分段使用的纯文本，再进行字符数判断、分段和 TTS；绝不把 Markdown 原文直接传给 speech CLI。仅去除格式标记，不改写正文内容或顺序，保留适合朗读的标点和段落边界：

- 若文件开头有 YAML Frontmatter（从开头 `---` 到下一个独占行 `---` 或 `...`），整块删除，不朗读。
- 删除独占行形式的 Markdown 分隔线（`---`、`***`，允许行首/行尾空格）。不要把正文里的普通破折号误删。
- 标题行去除开头的 `#` 至 `######` 标记及其后空格，保留标题文字；标题仍按原顺序保留，并与正文段落分隔。
- `**粗体**`、`__粗体__`、`*斜体*`、`_斜体_` 去掉包裹标记、保留其中文字。
- 图片语法 `![alt](URL)` 默认整项删除，不朗读 alt 或 URL；链接语法 `[文字](URL)` 只保留“文字”。
- fenced code block（以三反引号围栏或 `~~~` 围栏开始、对应围栏结束）默认整块删除，不朗读代码内容；围栏外普通正文照常保留。
- 保持原段落先后与句读；删除语法后清理纯空行堆叠，但不要把相邻自然段无故粘连。
- Markdown 清理后的朗读纯文本须先完成下文“TTS 朗读规范化”，规范化后的副本才是后续分段、字符数统计、续跑清单及 TTS 的文本来源。朗读用文本及分段文件只存放在本次任务临时目录；按既有成功/失败规则保留或清理。
- 调用 CLI 时必须通过参数数组/安全引用将完整朗读文本作为一个独立参数传入，不能拼接成 shell 命令。参数位置应在所有 CLI 选项之后；若朗读文本首字符是 `-`，先按 `speech speak --help` 核实参数终止符是否受支持，支持时用 `--` 隔开选项与文本。若不支持，改用不会改变朗读内容的安全参数传递方式（例如仅在参数开头添加一个换行作为前缀）。无论如何，正文中间的 `--`、`---` 必须作为文本内容传递，绝不可被 shell/CLI 当成选项，也不得删改正文来规避。

非 Markdown 输入不做 Markdown 转换，但同样可在朗读副本中执行下文的十进制规范化。

## TTS 朗读规范化

在 Markdown 清理完成后、字符数判断和长文本分段之前，仅对待朗读副本进行十进制数字的中文口语化，防止 speech CLI 将小数点当作句号。不得改动原始 Markdown 文件、参考声音或 reference transcript。

- 只处理 ASCII 数字组成的 `数字.数字` 十进制形式，例如可用 `(?<![0-9.])([0-9]+)\.([0-9]+)(?![0-9.])` 定位候选；须先识别并保护 URL、邮箱、文件路径及多点版本号/IP 地址等非十进制结构，不在这些结构内部局部替换。
- 整数部分按中文数值读法转换（`0` → `零`，`1` → `一`，`25` → `二十五`）；小数点转换为 `点`；小数部分逐位转换（`88` → `八八`），保留小数尾部的零。不自行四舍五入或改变数值。
- 数字外的单位、字母、标点和段落顺序原样保留。例：`1.7B` → `一点七B`，`0.5B` → `零点五B`，`0.88` → `零点八八`，`25.36` → `二十五点三六`。
- 不替换所有 `.`，不处理独立整数；普通英文句点、省略号及非十进制内容保持不变。已有中文形式不再次转换。
- 保存/记录规范化后的朗读副本，后续分段与断点恢复沿用该副本；不要对已有成功分段临时采用不同转换规则。本步骤不改变 A–E 模式及音频生成/合并策略。

## 长文本 TTS

### 何时分段及如何切分

- 待合成正文（Markdown 输入先转换为朗读用纯文本，再完成十进制朗读规范化；不含空白字符）超过 **1,200 个字符**时自动进入长文本流程；1,200 字及以内一次生成。模式仍严格遵循上面的 A–E 交互，同一任务只询问一次；没有用户选择不得开始合成。
- 改用较小语义块，每次 TTS 调用目标为 **80–200 个非空白汉字/字符**，以约 **150 字符**为组合参考；不再使用 500–900 字符的大块。语义完整优先，必要时允许略超。
- 优先按自然段组织；短段（不足约 80 字符）与相邻语义关联段合并，不单独生成“问题是：慢。”等短碎片。保持段落顺序、段间换行和原有句读。
- 组合时，在自然段边界选择接近 150 字符、通常不超过 200 字符的位置；遇到标题、引出句及其解释内容时优先绑定，不为了字数拆散语义。标题与紧随其后的第一段同块。
- 长自然段仅按句号、问号、感叹号等完整句子边界拆分，绝不从句中硬切；单个超长句保持完整。末尾不足 80 字符的余块优先与上一块合并或在完整句界重新平衡，避免极短尾块。
- 分块后检查顺序及内容覆盖：按原序连接各块的非空白内容应与规范化朗读副本一致，防止准备文本时遗漏或重复。

### 风格和生成

- 全文先整体理解。A、C、D、E 所有分段使用同一模式和完全相同的风格参数。B 先从全文确定整体表达基调；只有明显的较大语义转折、情绪变化或重点处才调整指令，不逐句换风格，保持自然、克制、连贯，避免分段间像不同配音者。
- 每个语义块执行：独立调用 speech CLI 生成 WAV → Qwen3-ASR 0.6B 4bit 本地转写 → 宽松完整性比较 → 记录 PASS / REVIEW / FAIL。均使用固定的 CosyVoice、参考声音、reference transcript、语言和本次 A–E 风格策略。**exit code 0 只证明命令退出成功，不能证明朗读完整。** PASS 才作为已验证块接受；REVIEW 按下文不确定性例外处理，FAIL 绝不进入合并。
- 必须持久保留 `reading-text.txt` 和 `segments.json`，保存至 `~/Downloads/<最终 WAV 文件名去扩展名>-records/`。每块另建 `block-NNN/attempt-1/` 至 `attempt-3/`，每次保存完整原始朗读文本、TTS WAV 与日志、ASR 转写与日志、覆盖率、最长连续未匹配字符数、逐句结果、重复/顺序异常证据、PASS / REVIEW / FAIL 及原因、耗时。清单记录生成次数、重试次数（生成次数减 1）、最终状态和选用 WAV 路径。禁止覆盖此前尝试的诊断文件。
- 恢复时沿用同一份朗读文本、风格和清单，不重跑已经接受的 PASS 块或已记录的 REVIEW 块；已生成但未校验的 WAV 先执行 ASR，不直接跳过校验。
- `speech speak --help` 已确认 CosyVoice 支持 `--seed`。**长文本每次任务使用固定 base seed，默认为 42**，在任务清单中保存 `base_seed`。所有块首次生成均显式传入 `--seed <base_seed>`；同一块第一次 FAIL 重试用 `base_seed + 1`，第二次 FAIL 重试用 `base_seed + 2`，即 `seed = base_seed + attempt - 1`（attempt 从 1 开始）。默认三次机会分别为 42、43、44。
- 每次尝试必须记录实际 `seed` 与调用参数；断点恢复沿用已保存的 base seed 和累计 attempt，不重新抽取或重置。PASS 或 REVIEW 块不因 seed 策略改变而重新生成；旧任务已有合格块也不自动回填重做。
- 固定 seed 用于减少同块重复生成的漂移，不保证不同块语速完全一致。已验证相同 seed、文本和参数可能生成完全相同的 PCM，因此 FAIL 重试禁止继续使用相同 seed。此策略只调整长文本任务，短文本保留现有行为。
- 每段单独记录 CLI `Time` 和 RTF；累计各段 CLI `Time` 作为 TTS 实际生成总耗时。墙钟任务总耗时从开始处理/首次合成前计时至最终 WAV 验证完成。

### Qwen3-ASR 本地内容完整性校验

- 只使用已经下载的 `aufklarer/Qwen3-ASR-0.6B-MLX-4bit`。先检查本地缓存存在；缺失则停止并告知，禁止下载其他 ASR 或 ForcedAligner，也不自行补下载。使用离线环境 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`；如 CLI 仍尝试实际下载则停止。
- 每次调用示例（按参数数组/安全引用传路径）：
  `speech transcribe --engine qwen3 --model aufklarer/Qwen3-ASR-0.6B-MLX-4bit --language chinese <本次块 WAV>`，CLI 使用固定的 `/opt/homebrew/bin/speech`。参数不确定先看 `speech transcribe --help`。
- **不要用 `--context` 或其他方式把应读原文提示给 ASR**，避免识别器补出没有读的句子。保存 ASR 原始输出及统计，之后才与本块原文比较。

#### 宽松归一化与逐句比较

- 只对比较副本忽略标点、空白和英文大小写，统一已知数字/中文读法。保留原始句子、段落和边界用于逐句校验；原始记录、TTS 输入不改动。
- 容忍少量普通 ASR 错字和英文专名/型号/缩写的音译、错拼：例如 haoqin-25、Pi、Codex、Speech Studio、CosyVoice、Qwen、CLI、RTF、TTS。可以记录有依据的读音等价关系或在对应的局部专名跨度宽松匹配，但不得给 ASR 提示原文，不得全局删除专名/句子或忽略它们所在整句，不能用专名宽容掩盖相邻中文句子的消失。
- 整体覆盖率采用**保留顺序的匹配原文字符数 ÷ 归一化原文字符数**，可用字符级顺序对齐（例如 SequenceMatcher，关闭 autojunk）生成差异跨度。记录最长连续未匹配原文跨度；未匹配可能来自错识，不自动等同于真实漏读。
- **逐句检查是硬要求，短句不能忽略。** 以原句/语义段为单位，结合顺序对齐及局部宽松匹配判断句子是否出现、部分出现、缺失或不确定，保存每句的证据。不能只做无序词袋匹配；冒号引出内容应结合后续短句检查，不把“问题是：慢。”拆成无意义的单字而放弃验证。
- 同时检查 ASR 中较长重复片段和句子出现顺序；多出来的文本要判断是否为原文已经出现内容的重复，排除正常原文重复。小范围错拼、音译和少量插字不算大段重复或明显错序。

#### PASS / FAIL / REVIEW

- **PASS**：整体覆盖率 ≥85%，没有明确整句缺失、明显较长连续缺失、明显大段重复或明显顺序错乱。逐句检查也必须通过；高覆盖率不能豁免短句。
- **FAIL**：高置信度的整句/语义段缺失（包括“问题是：慢。”这类短句），或连续较长内容缺失、明显大段重复、明显顺序错乱等完整性错误。连续未匹配 ≥20 字符是强异常候选，但须结合上下文和专名错识判断置信度；短于 20 字符的完整句子也可 FAIL。
- **REVIEW**：差异主要可能来自专名、型号、缩写、ASR 自身不确定，或无法确定短句是否真实漏读。覆盖率不足 85% 但可能主要来自这些差异时不要直接 FAIL。保留记录，不自动判定音频失败，不因 REVIEW 自动重生成；如出现明确内容缺失证据则升级为 FAIL。
- 已人工确认的诊断经验：旧 21 块任务第 2、12、20 块是真实漏读；第 5 块完整、仅 haoqin-25 被 ASR 错识。用于校准判断原则，不按固定块编号硬编码结论。

### FAIL 自动重试与断点恢复

- FAIL 当前 WAV 不被接受。保留其 WAV、TTS/ASR 日志和比较证据，**仅重新生成当前块**，再完整执行 ASR 校验。正文、参考声音和既定风格保持不变，不擅自改写文本或切换模型；只有 seed 按任务策略依次改为 base seed + 1、base seed + 2，禁止重复失败尝试的 seed。
- **首次生成 + 最多 2 次自动重试，共最多 3 次 TTS 生成机会。** 一次变为 PASS 或 REVIEW 即停止自动重试，分别按已验证或待复核状态记录；不会重跑此前成功块。
- 第三次仍 FAIL：停止后续生成和最终合并，不声称成功；告知失败块号、显示完整朗读文本及三次 ASR 结果/判定原因，保留全部诊断文件，等待用户决定。不能重开会话/任务来静默重置重试额度。
- TTS 运行失败/输出无效，或 ASR 执行失败/无有效转写属于执行错误，不得冒充内容 PASS 或 REVIEW；记录并停止，用户决定续跑。不能因 ASR 故障跳过检查合并。
- 用户要求继续时，仅从失败块或未完成块继续；已接受块不重生成，清单保留累计尝试次数。重试额度耗尽后须有用户明确授权新的处理方案。

### 合并与验收

- **合并门槛**：每块都完成 TTS 与有效 ASR 比较，所有最终状态均为 PASS 或已记录并保留证据的 REVIEW，且没有未解决 FAIL、待处理块或执行错误。REVIEW 不等于内容已验证，但按用户规则不阻止合并；最终报告必须明确提示这些待复核项，不可宣称全块 PASS。
- 本机已存在 `/opt/homebrew/bin/ffmpeg`，无需安装新依赖。达到合并门槛后按原顺序，仅使用每块清单指定的最终选用 WAV 合并为一个最终 WAV；在相邻分段间加入 **0.25 秒**短静音。可先用 `anullsrc` 生成所需静音 WAV，再以 concat demuxer 按“音频段、静音段、音频段……”建立任务目录内的清单，执行 `ffmpeg -f concat -safe 0 -i <清单> -c:a pcm_s16le <最终临时 WAV>`。如输入参数格式不一致，使用 ffmpeg 显式统一为单声道、24 kHz、PCM signed 16-bit 后合并；不得仅拼接 WAV 文件字节。
- 最终输出使用 `~/Downloads/my-voice-tts-<唯一时间戳>.wav`，不得覆盖已有文件。合并完成后用 `afinfo` 验证可读性、时长、单声道/采样格式，并检查文件非空；成功后将最终 WAV 作为唯一主要结果。
- 最终 WAV 验证后只可清理可重建的合并清单、静音等临时文件；**持久保留每块每次尝试的 WAV、原文、ASR 转写、日志及比较结果**，连同最终朗读文本和清单，供漏读复核及续跑。失败时也全部保留，禁止自动清理诊断材料。

### 长文本完成报告

报告最终 WAV 路径（若被阻断则明确写未生成）、朗读字符数、总块数、音频时长、A–E 模式与风格、records 路径；B 模式另简述全文表达策略。另报告：
- 首次 PASS 数、最终 PASS / REVIEW / 未解决 FAIL 数；曾发生 FAIL 的块数、失败尝试次数，区分统计口径。
- 自动重生成块数与额外生成次数、每块最终状态；逐项列出 REVIEW 原因，不能把 REVIEW 隐藏在成功统计中。
- 本次 `base_seed`；每个发生重试的块按尝试顺序实际使用过的 seed（例如 42 → 43 → 44），以及最终选用尝试和 seed。
- ASR 校验累计推理耗时及调用墙钟耗时；TTS 累计 CLI `Time`，**包括失败诊断与所有重试尝试**，缺少统计时明确说明，不猜数。
- 整体任务墙钟总耗时（含分段、加载、ASR、重试、合并和验收）；整体 RTF = 累计 TTS 实际生成耗时 ÷ 最终音频时长，注明包含重试，ASR 耗时单独列出。未合并时不报告虚构的最终时长或 RTF。

## 执行

- 默认文件名使用清晰、唯一的名称，例如 `~/Downloads/my-voice-tts-YYYYMMDD-HHMMSS.wav`；如用户明确指定路径/文件名则遵从。先确认目标不会覆盖已有文件；若冲突，换一个唯一名称。
- 通过参数数组或安全的 shell 引号传递完整文本、transcript、风格和路径；避免文本中的引号/特殊字符导致命令注入或参数拆分。
- 记录命令开始和结束的墙钟时间；总生成耗时从启动 `speech speak` 前至其退出后计算，报告秒数。
- 使用 `--verbose` 获取合成统计；成功后检查输出 WAV，并用 `/usr/bin/afinfo`（macOS）读取音频时长。报告 CLI 给出的 synthesis `Time`（实际生成耗时）和 `RTF`；同时报告命令总墙钟耗时。如 CLI 未给出相关统计，明确写“未提供”，不要猜算冒充 CLI 数据。
- 合成失败、缓存缺失、输出文件无效时如实说明，不声称成功；不得为了排障下载模型。

## 命令参数模板

基础参数：

```text
/opt/homebrew/bin/speech speak --engine cosyvoice \
  --voice-sample /Users/world/Library/Caches/audio.soniqo.studio/references/haoqin-25-52791d24.mp3 \
  --cosy-reference-transcript '<固定参考音频文本>' \
  --language chinese --verbose -o '<输出 WAV 路径>' '<待合成文本>'
```

B 模式根据全文判断是否需要风格指令；C、D、E 模式均添加 `--cosy-instruct '<风格指令>'`（D 使用固定完整预设原文，C 使用映射后的英文风格名）。A 模式禁止传该选项。长文本每段沿用同一任务的选项与风格策略，并额外显式添加 `--seed '<base_seed + attempt - 1>'` 的实际整数值；首次统一使用 base seed，FAIL 重试递增。实际执行前按 CLI help 确认参数，并确保引用/转义安全。
